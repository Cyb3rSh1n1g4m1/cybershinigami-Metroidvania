## HIGH

### game/scripts/player.gd:250  [gd-player-combat]
facing = signi(dir) narrows the float axis value to int, so any analog-stick input with |axis| between the 0.2 deadzone and 1.0 truncates to signi(0)=0 and sets facing to 0.

*Scenario:* On a gamepad (joypad axes are bound in project.godot), tilt the left stick partially or simply release it (the axis always passes through 0.2..1.0): dir becomes e.g. 0.5, signi(0.5) narrows to 0, facing=0 and sticks there. Next dash executes velocity=(0*400, 0) -- the player freezes in place (hovering if airborne) for 0.15s while the cooldown is spent; attacks use offset Vector2(0*36,0) centered on the body and pass take_hit(1, 0) so enemies get zero knockback; line 248's signi(dir) != facing also fires a spurious turn animation. Keyboard input (exactly +/-1.0) never shows it, which is why it survives testing.

### game/scripts/title.gd:135  [gd-ui-world]
START never resets run state (Game.abilities, Game.soul_bytes), even though pause.gd line 343 explicitly defers 'starting a fresh run' to the title screen, so quit-to-title leaks the old run into the new one and permanently loses the integrity upgrade.

*Scenario:* Pick up the 'integrity' module (player.max_integrity 5->6), then ESC -> QUIT TO TITLE -> START: the freshly instanced player is back at max_integrity 5, but Game.has('integrity') is still true so upgrade_module.gd:36 marks the pedestal spent and the +1 can never be re-acquired that session; double_jump and all soul bytes also carry into the supposedly fresh run (HUD seeds itself from the stale Game.soul_bytes).
